# reBot 关节调试界面

浏览器入口为 `http://192.168.127.10:8765/`。

已配置 `rebot-panel.service`，RDK 开机联网后自动以 `--standby` 启动网页。
电脑直接打开上面的地址即可，不再需要 SSH 或一直保留终端。开机只提供网页和手柄输入预览，
不会打开 USB2CAN、发送 CAN、使能电机或恢复任何旧运动任务。可靠支撑机械臂后，在网页
勾选支撑确认并点击“连接机械臂”；七轴反馈通过后仍需用户手动启动重力补偿/遥操。

在 RDK 的 SSH 中查看服务、日志或禁用自启：

```bash
systemctl status rebot-panel --no-pager
sudo journalctl -u rebot-panel -n 50 --no-pager
# 只取消下次开机自启，不影响当前运行：
sudo systemctl disable rebot-panel
```

`sudo systemctl stop rebot-panel` 会停止当前服务；`restart` 会停止并重启。仅在已可靠支撑、
停止运动并确认失能后执行，不能在依赖软件支撑机械臂时操作。服务进程异常退出时，systemd
会等待 5 秒再启动一个全新的待机网页，绝不恢复遥操/重力补偿。网络地址尚未就绪时也会重试。

服务定义位于 `deploy/rebot-panel.service`。如需重新安装（先停止并确认机械臂失能）：

```bash
sudo install -m 0644 deploy/rebot-panel.service /etc/systemd/system/rebot-panel.service
sudo systemctl daemon-reload
sudo systemctl enable --now rebot-panel.service
```

自启服务运行时不要同时手动启动第二份服务。如仅需排查手动启动，先安全停止服务，再运行：

```bash
cd ~/reBotArm_control_py-main
./run_rebot.sh -u panel/server.py --standby
```

手动启动时需保持该终端运行。不带`--standby`的旧命令仍直接连接硬件，启动前必须托稳。

硬件连接使用达妙 USB2FDCAN 原生 USB 通道 0，与此前安装的官方 MotorBridge SDK 及 libusb 兼容库配合。待机初始不创建CAN工作线程；用户连接后USB热插拔仍沿用原有“新进程→七轴失能核验→等待手动启动”恢复，不会恢复旧任务。

## URDF 三维预览

主页面从同一份硬件配置解析 URDF 的关节轴、安装变换和 STL 外形。J1～J6 使用面板角度反馈。J7 实测角度越大夹爪越往里收：49.3° 最大张开，实测开口 60 mm；241.3° 达到收拢限位，仍有 8.5 mm 开口。两点之间按角度线性估算开口，在模型中两指对称移动；失联时保留最后有效姿态并标注。估算仅供显示，不替代量具，也不改变任何电机限位。浏览器不能启用 WebGL 时回退到二维示意。

视图源码位于 `panel/viewer/`，在开发机执行 `npm ci`、`npm run build` 生成 `panel/static/urdf-viewer.js`。部署时与其他静态资源一起复制；RDK 和浏览器运行时不访问 npm 或 CDN。浏览器测试在仿真端注入角度，验证模型更新、视角旋转及反馈中断提示。

### D435i 彩色预览

在控制台点击「开启相机」后，RDK 以 640×480、6 帧/秒采集 D435i 彩色画面。同一时间允许一个网页预览，切走页面、手动关闭或断线约 4 秒后释放设备。只保留最新一帧于内存，不录制、不写盘、不经外网。采集用 RDK 已安装的 FFmpeg，低优先级运行；按 D435i 的 USB 和视频接口标识选择设备，并不固定写死 `/dev/video4`。预览不依赖电机连接，也不控制机械臂。当前不提供深度预览、相机画面上的模型叠加或自动抓取。

## 使用

### 控制前检查与停止互锁

面板的关节在线状态以新鲜的 CAN 状态反馈为准，不再由寄存器查询刷新。轴反馈超过 150 ms、时间戳异常或数据非有限时不允许使用该轴启动；持续重力与遥操需要七轴新反馈。执行前二次检查反馈序号，避免刚接受请求就依据旧位置启动。点动及空闲轮询不做同步寄存器读取，遥操的模式检查仍只放在使能前。

收到停止请求时先撤销未执行的任务并锁住新启动，待工作线程完成失能指令再解除锁。点动故障时不发送卸力位置指令，直接尝试失能；正常取消仅在位置反馈仍新鲜时保留既有短时卸力。此功能是软件停止，不替代独立急停。补偿模型、运动速度、增益和现有保护阈值没有放宽。参见 `panel/test_feedback_stop.py`、`panel/browser_usb_reconnect_check.py`。

后续优化按实测推进：先比较关闭/打开 D435i 时的控制周期、各轴真实反馈间隔和停止原因；再用当前末端负载检查 J2/J3/J4 多个姿态的漂移、起停和换向，区分模型偏差、通信抖动与静摩擦；最后独立验收夹爪软端点和限力，再接入手柄夹取。仿真测试不能用来确认真机刹停距离或补偿精度。

### USB2CAN 自动重连

保持面板启动命令运行，重新插入 USB2CAN 后会自动重建连接，无需手动重启脚本。未插入时网页显示等待，连接后显示正在确认七轴失能。七台电机必须都有新的实时反馈且状态为失能，控制按钮才会解锁。若只插USB而电机未上电或CAN未接好，会继续等待确认，不会使能电机。

拔出或重新枚举时立即取消待执行任务、使反馈缓存失效。重连绝不恢复旧重力/手柄/点动任务，网页的手柄核对框也会清掉。恢复后需要用户重新核对并手动启动。重连握手会向七轴发送失能，请全程支撑机械臂，不能依赖软件恢复来维持负载。

SDK内部保存进程级USB句柄，因此使用项目内的父进程监督服务子进程。只在明确的USB恢复请求退出码75时启动新子进程，彻底丢弃旧SDK句柄。普通程序错误、用户停止不会自动续启。等待USB期间保留网页，切换子进程时页面会短暂重连。该机制不安装系统开机启动、不修改固件、网卡、IP、路由或DNS。

重连保护测试见 `panel/test_usb_reconnect.py`，网页恢复互锁测试见 `panel/browser_usb_reconnect_check.py`。后者只模拟状态返回，检查没有自动提交运动请求。

## 官方持续重力补偿

页面直接复用官方 `GravityCompensation`，从当前位置启动，使用官方 Pinocchio 模型和配置中的 Kp/Kd、方向系数、0.5 秒增益渐变以及 500 Hz 控制频率。J1～J6 持续重力补偿，J7 按官方实现保持当前位置。持续时间不限，也取消首次试验的相对起点 15° 位移限制。

用户已确认 J4 75%、其余轴 100% 可满足当前姿态的补偿，网页与配置默认值改为此组合。仍提供 J4 30%～100% 共 15 档，每档增加 5%。前后端共用服务端档位表，实际倍率保存在每次运行日志中。运行中锁定倍率，停止并确认失能后换档，再启动生效。重新打开网页会同步显示正在运行的实际档位。

## 连续遥操 continuous-mit-v11（夹紧保持的方向化位移判定）

修复已实测的误撤力：J7松RT后的HOLD阶段，继续向内压缩超过2°曾被当成接触失稳，

- 超过12°的持续收拢，或从已到达的最大收拢位置反向张开超过2°，须至少3帧新反馈、
  持续150 ms才进入受控暂停。单帧偏移不能触发，重复缓存不能完成确认。

  重置压缩余量或增加力矩。明确夹紧结束时捕获新的保持起点，但不抹掉反向张开的证据。
- 有效LB＋LT优先进入原有撤力/张开流程，不把操作者要求张开误判为失稳。
- 原机械/软件端点、2 N·m软件力矩上限、速度/通信/驱动/温度保护均保留。

## 持续重力模式的启停与保护

正式网页的纯重力补偿继续使用原有官方控制器、URDF、方向和倍率（默认 J4 75%、其余 100%）。下文的 100 Hz 重力改进仍为离线验证方案，不随 J7/腕部更新默认启用。该方案启动时以第一帧实测位置为起点，把补偿前馈从零渐入，保持增益同步平滑过渡到柔顺增益。请在任何渐入和卸力过程中可靠支撑机械臂。

纯重力控制按 100 Hz 目标运行，每轮只读缓存并轮转请求一轴反馈，不同步等七轴回复。发送前校验 CAN 反馈、驱动状态、温度和模型力矩；SDK 发送失败会报告出错关节。故障时不追加卸力位置指令，而是逐轴尝试失能。手柄轨迹、增益和速度限制未修改。

重力日志分别记录模型前馈、经渐入/滤波且整轮 SDK 发送调用完成的命令、驱动反馈、控制周期和各轴 RX 序号/年龄，另保存启动阶段样本。SDK 调用成功不等于驱动器已收到，更不是外部力测量。官方 URDF 给末端固定的 0.5 kg 惯性，未包含抓取物。拖动丝滑程度和实际负载补偿须在有支撑的现场多姿态验证后才能下结论。

关闭网页、浏览器断网或电脑休眠后，重力补偿仍在 RDK 本地持续运行。重新打开页面可以查看和停止。点击“停止重力补偿”、顶部停止或 Esc 后，在当前位置约 0.5 秒平滑卸载并失能，请托稳机械臂。服务退出同样结束控制。停止流程采用当前位置卸载，官方示例中的自动归零运动没有接入此按钮。

保护仍包括七轴反馈/寄存器链路核验、驱动状态、65℃温度阈值、无效数值、控制线程退出及持续 100 ms 的硬超速。面板的速度阈值为 J1～J3 2 rad/s、J4～J7 3 rad/s，属于面板附加保护。重力前馈超出电机协议量程时也会失能。关节碰撞、线缆缠绕和模型偏差需现场观察，这一模式不会自动规划避障。
